Kelompok 1: Tanpa Perlu Mendaftar (Otomatis Terkoneksi, Direct 
Clone, Direct Pull, dan Umpan Publik) 
Seluruh sumber daya di dalam Kelompok 1—yang juga mencakup seluruh komponen 
perangkat lunak dari Kategori 3 pada cetak biru VPS—tidak memerlukan pembuatan akun, 
autentikasi OAuth, maupun kartu pembayaran. Agen AI dapat langsung mengintegrasikan titik 
akhir ini ke dalam skrip otomatis (curl atau httpx), menarik bobot model melalui antarmuka baris 
perintah (llama.cpp, Ollama, vLLM, Docker Model Runner), atau melakukan git clone secara 
instan ke lingkungan eksekusi lokal. 
1A. Umpan Proksi Publik, API Rotasi Tanpa Kunci & Jaringan Otomatis 
(Langsung Terkoneksi) 
Pada lapisan rotasi IP dan titik akhir publik nir-autentikasi, ketergantungan tunggal pada 
monosans/proxy-list memiliki risiko kejenuhan alamat IP akibat tingginya pengguna konkuren 
yang memanen dari satu daftar yang sama. Penelusuran mendalam terhadap ekosistem 
pemanen proksi terbuka mengungkap repositori dengan frekuensi pembaruan jauh lebih cepat 
(setiap 1 hingga 10 menit), volume kolam IP yang jauh lebih masif (hingga 5.610+ proksi aktif 
per pemindaian pada TheSpeedX/PROXY-List dan 6.900+ bintang pada proxifly/free-proxy-list), 
serta jalur akses melalui jaringan distribusi konten (cdn.jsdelivr.net dan fastly.jsdelivr.net) untuk 
menembus pembatasan laju permintaan (rate-limit) atau pemblokiran ISP terhadap domain 
raw.githubusercontent.com. Selain itu, penyediaan titik akhir REST API nir-kunci seperti 
ProxyScrape v2 dan GeoNode API beserta perkakas verifikasi berbasis Go 
(WangYihang/Proxy-Verifier) menjamin bahwa agen tetap dapat memperoleh IP bersih yang 
teruji bebas cache meskipun seluruh repositori GitHub mengalami gangguan layanan.

huihui-ai—seperti Huihui-Qwen3.8-27B-abliterated-GGUF dan

Penegakan wajib terhadap format tensor nir-eksekusi (.safetensors dan .gguf) yang 
dikombinasikan dengan pemindaian statis protectai/modelscan serta tata kelola runtime 
Microsoft Agent Governance Toolkit menjamin bahwa kebebasan eksplorasi tanpa sensor 
tersebut sepenuhnya terlindung dari ancaman penyusupan malware serialisasi pickle maupun 
eksekusi perintah destruktif. 
Sebagai fondasi keberlanjutan jangka panjang, integrasi antara ketahanan akuisisi data web 
dan siklus ekonomi mandiri (self-sustaining compute loop) memastikan agregator mampu 
mendanai ekspansi perangkat kerasnya sendiri secara otonom. Menggantikan perayap web 
tunggal dengan rantai pengalihan spider-rs/spider \rightarrow D4Vinci/Scrapling (scrapling-rs) 
\rightarrow Crawl4AI (terisolasi secara internal) yang disuplai oleh lebih dari 15 umpan proksi 
multi-CDN (TheSpeedX, proxifly, monosans, jetkai, roosterkid, jhao104/proxy_pool) 
menghilangkan risiko kegagalan ekstraksi data akibat perubahan struktur DOM maupun 
proteksi Cloudflare Turnstile. Di hilir, perpaduan antara gerbang pembayaran tanpa kartu Visa

## PROTOKOL 2: ALUR Dual-Repo (WRITE-CLEAN, DEPLOY-LOCKED)
1. **Sumber Konteks Tunggal:** Saat membaca kode untuk debugging atau penambahan fitur, SELALU tarik kode dari `private_repo_url` (Shadow Vault) yang terdaftar di tabel `infrastructure_registry` Turso. Jangan pernah membaca konteks dari `public_repo_url`.
2. **Standar Shadow Vault (Private Repo):** Kode yang di-commit ke `private_repo_url` harus 100% bersih (Clean Code), modular, memiliki komentar dokumentasi yang jelas, dan siap diaudit oleh manusia/pembeli kapan saja.
3. **Standar Public Release (Public Repo):** Sebelum melakukan push ke `public_repo_url`, Anda wajib menjalankan pipeline kompilasi/obfuscation (mengubah modul inti menjadi binary `.so`/`.pyd` dan menghapus seluruh komentar internal).
4. **Sinkronisasi Turso:** Setiap kali rilis selesai, simpan hash commit Private, hash commit Public, dan kunci dekripsi rilis ke tabel `release_snapshots` di Turso.
